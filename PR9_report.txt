Доработка проекта
Проанализированы таблицы rooms, users, materials, estimates старой SQLite.
Созданы модели Room (name, length, width, height), User (name, phone, email),
Material (name, unit, price, coverage), Estimate (room, user, materials,
materials_cost, works_cost, total). id создаются Django автоматически.
Для размеров, покрытия и денежных сумм выбраны DecimalField; добавлены
ограничения положительности размеров, неотрицательности сумм и равенства
total сумме затрат. User представляет заказчика, отдельно от авторизации.

Смета связана с помещением и заказчиком через ForeignKey с PROTECT и
related_name=estimates; состав материалов — ManyToManyField. Созданы
и применены rooms/0001_initial и estimates/0001_initial. Выбрана стратегия
создания управляемых Django таблиц в db.sqlite3 без изменения базы ПР7.
Команда import_pr7 читает data/renovation.sqlite только для чтения и
транзакционно записывает данные через ORM, сохраняя идентификаторы и суммы.
Связи материалов восстановлены из JSON. Повторный запуск безопасен, конфликт
откатывает всю операцию. Сохранены 3 помещения, 1 заказчик, 2 материала,
1 смета с двумя материалами; смета №1: 200 + 500 = 700 руб.

Все представления переведены на ORM. Сохранены главная, списки и карточки
помещений и смет, поиск площади, статистика. Добавлены поиск названия и
поиск смет по помещению, заказчику и email; фильтры помещения, заказчика,
диапазона стоимости и исключения бесплатных смет; безопасная сортировка;
пагинация по 5 записей с сохранением GET-параметров. Предусмотрены ошибки
ввода, пустые выборки и HTTP 404. Отсутствующие в предметной области даты
бронирования и отмены из примера Roomly не вводились искусственно.

Реализованы более 15 ORM-выражений: получение коллекций и отдельной записи,
filter, exclude, Q, F, values, select_related, prefetch_related, обратные связи,
order_by, annotate, aggregate, Count, Sum, Avg, Min, Max и Paginator.
CRUD проверен на тестовой базе; модели зарегистрированы в админке.
Обновлён README с моделями, связями, запуском, миграциями, импортом,
fixture-командами и таблицей ORM-запросов для защиты.

Проверки
python manage.py check — ошибок нет.
python manage.py makemigrations --check --dry-run — изменений нет.
python manage.py showmigrations — миграции rooms и estimates применены.
python -m pytest -v — 21 тест пройден.
python -m flake8 . --extend-exclude=venv — замечаний нет.
Интеграционные тесты покрывают страницы, расчёт площадей, связи,
защиту удаления, ограничения БД, поиск, сортировку, параметры, пагинацию,
агрегаты, повторный импорт и откат. Исходная база ПР7 не изменялась.
